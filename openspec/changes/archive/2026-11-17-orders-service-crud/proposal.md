# Proposal

Risk class: R2 — выбран автором в целях демо; по осям оценка была бы R1, повышение осознанное (правило «при сомнении — выше»).
- Данные: internal — демо-заказы в памяти, без ПДн, секретов и платежей (допущение: `customerName` — условное имя).
- Среда: dev — демо, в прод не идёт, данные теряются при перезапуске.
- Радиус влияния: один сервис (`orders`), потребителей нет.
- Регуляторика: нет.

Story: —

Intent: `docs/intent/20261117-orders-service-crud.md` (INTENT-20261117-orders-service-crud, репозиторий monorepo).

## Why

Нужен демонстрационный сервис заказов, на котором прогоняется весь путь AFSDD (intent → спека → тесты → реализация → review → evidence). Внутренним клиентам API нужно создавать, читать, изменять и удалять заказы; сервиса и API пока нет.

## What Changes

- Новый сервис `orders` (`orders-service`) в репозитории `a-erpuo-demo-service`: Java 21, Spring Boot 3, Maven.
- Новый REST API заказов: `POST /orders`, `GET /orders`, `GET /orders/{id}`, `PUT /orders/{id}`, `DELETE /orders/{id}`.
- Валидация входных данных: невалидные данные — 400; несуществующий `id` — 404; единый формат тела ошибки.
- Хранение заказов в памяти процесса (по ADR-0001), потокобезопасное.
- В глоссарий добавлены термины, которых там не было: позиция заказа, статус заказа и др. (`domain/02-domain-glossary.md`).

Breaking changes нет: существующего API нет.

## Impact

- Сервис и capability: `orders/order-crud` (новая).
- Внешний контракт: REST API `/orders` (новый, пять операций); других контрактов (Kafka, БД) нет.
- Затронутые репозитории: `a-erpuo-demo-service` (код, пока пуст), `specs-repo` (спека, глоссарий).
- «Что нельзя ломать» (`domain/01-product-context.md`, `domain/00-start-here.md`): `GET /orders/{id}` не ломаем — эндпоинт появляется впервые, контракт фиксируется этой спекой; инвариант «заказ однозначно идентифицируется `id`» соблюдён (`id` генерирует сервис, неизменяем). Иных пунктов change не затрагивает.
- ADR: новый не нужен — хранение в памяти уже принято в ADR-0001, отступлений от `domain/03-architecture.md` нет (controller → service → in-memory repository).

## Non-goals

- БД и миграции, аутентификация и авторизация (запрещены без ADR, `domain/00-start-here.md`).
- Пагинация, фильтры и сортировка в `GET /orders`.
- OpenAPI/Swagger, Actuator, Dockerfile, CI.
- Идемпотентность `POST`.
- Специфицирование поведения при неверном `Content-Type`.
